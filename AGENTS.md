# Инструкции для работы с проектом

## Проект и стек

Прошивка ESP32 Dev Module управляет шаговым двигателем через DRV8825 и веб-интерфейс в собственной точке доступа. Используются PlatformIO, платформа `espressif32`, Arduino framework, C++, встроенные библиотеки `WiFi` и `WebServer`, а также HTML/CSS/JavaScript без отдельной системы сборки фронтенда.

- `src/main.cpp` — сервер, Wi-Fi, GPIO и выдача импульсов.
- `src/index.html` — страница управления, включаемая в прошивку через `board_build.embed_txtfiles` в `platformio.ini`.
- `include/move_command.h` — проверка числа оборотов и состояние движения; `test/test_move.cpp` — автономные C++ тесты этой логики.
- `include/command_gate.h` — одноразовая версия состояния для защиты от повторных и запоздавших команд; `test/test_command_gate.cpp` и `test/test_ui.js` проверяют протокол и восстановление интерфейса после ошибок связи.
- `README.md` — подключение оборудования и использование. `PROJECT_STATUS.md` — датированный снимок состояния; его сведения могут устареть.

## Сборка и проверка

Команды выполняются в корне проекта. Для сборки требуется PlatformIO; если `pio` отсутствует в PATH, на этой машине можно использовать `& "$env:USERPROFILE/.platformio/penv/Scripts/pio.exe"` вместо `pio` в PowerShell.

```powershell
pio run                         # сборка для esp32dev
pio run --target upload         # прошивка подключённой ESP32
pio device monitor --baud 115200 # последовательный порт
```

Для автономных тестов нужен `g++`; в PowerShell:

```powershell
g++ -std=c++11 -Wall -Wextra -pedantic -I include test/test_move.cpp -o "$env:TEMP/gruzdy-test-move.exe"
if ($LASTEXITCODE -eq 0) { & "$env:TEMP/gruzdy-test-move.exe" }
g++ -std=c++11 -Wall -Wextra -pedantic -I include test/test_command_gate.cpp -o "$env:TEMP/gruzdy-gate.exe"
if ($LASTEXITCODE -eq 0) { & "$env:TEMP/gruzdy-gate.exe" }
node test/test_ui.js # требуется Node.js
```

Сборка создаёт `.pio/build/esp32dev/firmware.bin`. После изменения HTML нужна повторная сборка и прошивка. Приложение работает на ESP32: после загрузки подключитесь к её Wi-Fi и откройте `http://192.168.4.1/`; настройки доступа и подробности — в README. Загрузка и проверка работы двигателя требуют подключённого оборудования.

## Правила изменений

- Сохраняйте существующий стиль: небольшие функции, отступы в два пробела в C++ и читаемый HTML/JavaScript. Не добавляйте зависимости без необходимости.
- Сохраняйте проверку входных параметров на сервере: целые обороты 1–1000 и допустимое направление. Проверка только в браузере недостаточна.
- Учитывайте активное движение и возможность остановки при изменении обработчиков, цикла или интерфейса. Не представляйте программную остановку по Wi-Fi как независимую аппаратную аварийную остановку.
- Параметры шагов, выводов и режима драйвера связаны с подключением оборудования: при их изменении проверяйте расчёты и обновляйте README. Счётчик импульсов не измеряет реальное положение двигателя.
- Не добавляйте реальные пароли в репозиторий и не распространяйте текущие значения по новым файлам. Не ослабляйте аутентификацию и проверку источника запросов без явного основания.
- Проверяйте изменения сборкой; при изменении логики движения запускайте автономные тесты и дополняйте их по необходимости. Изменения интерфейса и аппаратного поведения дополнительно проверяйте на устройстве, если оно доступно; иначе явно указывайте ограничение.
- Не перезаписывайте чужие незакоммиченные изменения. Перед работой проверяйте `git status`; обновляйте документацию, если меняются команды, подключение или поведение.

## Состояние на 9 ноября 2026 года

Страница вынесена в `src/index.html`; импульсы выдаются таймером, а запуск использует одноразовую версию состояния. Веб-сервер обрабатывает запросы последовательно, поэтому медленный запрос может задержать обработку остановки. Проверка на оборудовании необходима. Актуальный статус файлов определяйте через `git status`, а не по этому снимку.
